### Shell guard (run_shell)

15 destructive patterns blocked (`rm`, `rmdir`, `dd`, `mkfs`, `mkswap`, `chmod 777`,
`chown`, `>/dev/`, `format`, `wiped`, `wipefs`, `parted`, `fdisk`, fork bomb,
`>/dev/null && rm`). `force=True` bypasses.

| What you need | Tool |
|:---|:---|

### Key systems

#### Tool cache
Read-only tools (read_file, file_info, list_directory, search_files, semantic_search,
web_search) cached within a turn by (name, sorted_args). `clear_tool_cache()` called
at turn start by `run_agent_turn`. Write tools and streaming calls skip the cache.

#### Error hints
Every common failure path includes a `Hint:` line: read not found → "Try list_directory",
write blocked → "Use a path inside the workspace", edit mismatch → "Check whitespace,
try read_file first", run_shell error → "Check command and flag spelling", destructive
guard → "Use force=True", exit code 127 → "Command not found".

#### Conversation export
`/export` writes current conversation to `conversation_YYYYMMDD_HHMMSS.md` with
thinking in blockquotes, tool calls in code fences, tool results truncated to 500 chars.
Works in both terminal REPL and TUI.

#### Approval mode
`--approve` flag gates write_file, edit_file, and run_shell. Terminal: interactive
`[y/N]` prompt. TUI: auto-approve with visual indicator. Added to both `AgentConfig`
dataclass and CLI flag parsing.

#### Background shell tasks
`run_shell(background=True)` returns a task ID immediately. `task_status(id)` polls.
Registered in `_TASK_REGISTRY` in tools/__init__.py. Tasks cleaned by running test
teardowns and on agent shutdown.

#### Incremental tool execution
During SSE streaming, `_parse_stream` detects when tool call arguments form valid
JSON and fires `on_tool_ready(tc)`. `run_agent_turn` executes tools immediately and
marks them via `_fired_indices`. After the stream, only non-fired tools are executed.
When all tools were incrementally executed, the loop continues for the text reply.

#### Memory (memory.py)
Three-tier management applied on every save:
1. **Token-aware pruning** — `max_tokens=800_000`. Rough estimator (4 chars ≈ 1 token)
   prunes oldest turns, preserving tool-call sequences and turn boundaries.
2. **Tool result compression** — Tool outputs >6 messages from the tail are trimmed
   to their first 5 lines (previously 1).
3. **Conversation summarization** — Synthetic "Earlier in this conversation: …" message
   lists files read/written, commands run, and recent user prompts.

### TUI (tui.py)

- **Dark theme**: #111111 background, #1b1b1b surface
- **Streaming**: Thinking flushed on sentence boundaries (. ? ! :) or every ~400 chars,
  with `┃` left-border prefix. Content flushed on newlines or every ~300 chars.
- **Shell output**: streamed in real-time (dim) via `_ToolOutput` messages; stderr
  prefixed with `[stderr]`.
- **Thinking separator**: `▔▔▔ thinking ▔▔▔` header marks each reasoning block.
- **Parallel tools**: `⫼` icon for parallel calls, `⚙` for singles.
- **Plan display**: agent states plan as text before tool calls.
- **Markup safety**: all user/LLM content escaped via `_safe()`.
- **Multi-line input**: TextArea widget. Enter submits, Shift+Enter inserts newline.
- **Cancel**: Ctrl+C sets cancel flag, worker thread exits cleanly. Memory saved on cancel.
- **Queue architecture**: AgentWorker → thread-safe Queue → set_interval(50ms) drain loop.
- **Shared agent loop**: `run_agent_turn()` in llm.py used by both TUI and terminal REPL.
- **Double-submit guard**: Enter ignored while worker is active.
- **Token usage**: displayed in status line.
- **Commands**: `/clear` resets memory, `/export` writes conversation, `/help` lists commands.
- **Input history**: Up/Down when empty cycles through submitted messages.
- **Session reuse**: one requests.Session per app session.
- **Worker error recovery**: exceptions push `_Error` to queue instead of crashing.
- **Approval mode**: `_approve` callback auto-approves with `⏳ approved tool_name` indicator.

### LLM agent loop (llm.py)

- **Incremental tool execution**: `on_tool_ready` fires during streaming when tool args
  are complete. Tools execute immediately; remaining executed after stream.
- **Parallel tool execution**: ThreadPoolExecutor for 2+ independent tools.
- **Session reuse**: One requests.Session per app session.
- **Progress checks**: Every 5 tool-using turns, agent assesses progress.
- **max_turns**: Default 100 (user controls via cancel).
- **Retry**: Exponential backoff (1s, 2s, 4s) on 429/5xx.
- **Streaming shell**: `on_tool_output` → `_run_shell` → Popen reader threads → real-time TUI.
- **Approval**: `approve_callback` gates write/destructive tools.

### Flags

```
  --workspace PATH    Set workspace root (default: cwd)
  --stream            Stream responses token-by-token (terminal only; TUI always streams)
  --quiet             Suppress tool execution logs
  --no-color          Disable ANSI colours (terminal only)

```

### Prompt (prompt.py)

- **Confirm before planning**: agent must confirm the plan with the user before starting
  a new feature.
- **Parallel tools**: tells the agent to batch independent tools in one response.
- **Multistep planning**: tells the agent to state the plan in 1-3 sentences before
  executing tools. Example: "I'll read config.py, search for references to the old key,
  then update all three files."


## 2026-05-11 — 400 bug fix (incremental tool execution ordering)

**Problem:** Every input returned a 400 error:
`Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`

**Root cause:** The incremental-tool-execution feature (streaming `_on_tool_ready`
callback) appended tool-result messages directly to the messages list *during*
the stream — before the assistant message (with `tool_calls`) was appended.
This created an invalid message order: `[user, tool, assistant]` instead of
`[user, assistant_with_tool_calls, tool, assistant_text]`.

**Fix (llm.py):**
1. `_on_tool_ready` now defers tool-result appends to a local list
   (`deferred_stream_results`). UI callbacks (`on_tool_start`, `on_tool_end`)
   still fire immediately for responsiveness.
2. Deferred results are flushed to `messages` AFTER the assistant message
   is appended — satisfying the API's ordering constraint. (First attempt
   put the flush before the assistant append — still wrong; corrected.)
3. The assistant message now keeps ALL `tool_calls` (not filtered to just
   `remaining`). Filtering would orphan deferred tool result references.
4. `call_deepseek`'s message-cleaning loop now strips all underscore-prefixed
   internal tracking fields (`_usage`, `_total_usage`, `_turn_count`,
   `_fired_indices`) to prevent them leaking into API requests.
5. The corrupted memory database (1.4 MB of messages from the broken
   session) was deleted — it persistently reproduced the ordering bug.

Verified: 212 tests pass, multi-tool interactions work, saved memory has
correct assistant_with_tool_calls → tool ordering.

## 2026-05-11 — Resilience features (4 new defenses against malformed tool calls)

**Context:** A malformed tool call in conversation memory can brick a session
(e.g., the 400 "tool message before assistant" bug). Production agents use
multiple layers of defense beyond what mini_agent had.

**Four new defenses implemented:**

### 1. Backward orphan detection (`memory.py` — `_clean_messages`)
Previously only had a forward check (truncate assistant if no matching tool
results follow). Now adds a **backward pass** that removes `tool` messages
whose `tool_call_id` doesn't match any *preceding* assistant's `tool_calls`.
Catches the "tool before assistant" ordering pattern that causes API 400s.

### 2. JSON repair on malformed tool args (`tools/__init__.py` — `_repair_json`)
Before `json.loads` in `execute_tool`, attempts to repair common LLM JSON
mistakes: trailing commas, single quotes, unquoted keys. Tries individual
fixes and combinations (7 repair strategies). Falls through to standard
JSONDecodeError if all fail.

### 3. Self-correction feedback loop (`tools/__init__.py`)
- `ToolResult` now has an optional `hint` field (included in dict/JSON on failure).
- `_build_error_hint()` constructs structured error messages: tool name,
  parse error, valid parameter names/types.
- Unknown tool errors include the list of available tools.
- Approval-denied errors explain why and suggest alternatives.

### 4. Circuit breaker for repeated identical tool calls (`llm.py`)
- `_tool_call_key()` hashes tool calls by name + normalized args.
- `_check_circuit()` trips when the same call appears ≥3 times in last 6.
- Before each API call, if circuit is tripped, injects a user message warning
  the agent to stop repeating and try a different approach.
- Tracking appended at all four tool-execution sites (deferred stream, single,
  parallel pool, and `_append_tool_result`).

**Tests:** `test_resilience.py` — 26 new tests covering all four features.
**Status:** 238 tests pass (212 + 26), lint clean.
