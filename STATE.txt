### Search + lookup strategy

| What you need | Tool |
|:---|:---|
| Function/class definition location | `find_symbol` (fast, startup-indexed) |
| All callers/references of a symbol | `find_usages` (reverse index from same scan) |
| Exact pattern (regex) | `search_files` with `regex: true` |
| Case-insensitive substring | `search_files` with `ignore_case: true` |
| Code by meaning / concept | `semantic_search` |
| Documentation, APIs, current info | `web_search` |

### Resilience defenses

| Defense | Where | What it does |
|---------|-------|-------------|
| Backward orphan detection | `memory.py:_clean_messages` | Removes tool messages with no preceding assistant |
| Forward orphan detection | `memory.py:_clean_messages` | Truncates incomplete tool-call sequences |
| JSON repair | `tools/__init__.py:_repair_json` | Fixes trailing commas, single quotes, unquoted keys |
| Schema validation | `tools/__init__.py:execute_tool` | Catches unknown/missing params before execution |
| Self-correction hints | `tools/__init__.py:ToolResult.hint` | Structured error feedback with valid params |
| Circuit breaker | `llm.py:_check_circuit` | Trips when same call repeats ≥3x in 6-call window |
| Transient messages | `memory.py:_clean_messages` | Injected context stripped from saved history |
| Tool cache | `tools/__init__.py:_TOOL_CACHE` | Read-only tools cached within a turn |

| Injection | When | Role |
|-----------|------|------|
| System prompt | Session start | system |

| Circuit breaker warning | When same call repeats | user |

### Key systems

#### Memory (memory.py)
Three-tier management on every save:
1. **Token-aware pruning** — preserves turn boundaries and tool-call sequences
2. **Tool result compression** — outputs >6 messages from tail trimmed to first 5 lines
3. **Summarization** — synthetic summary of files touched, commands run, recent prompts

#### Incremental tool execution
`_parse_stream` detects when tool call args form valid JSON and fires `on_tool_ready`.
Tools execute during the stream; remaining executed after. All tool_calls preserved in
assistant message for valid API ordering.

#### TUI (tui.py)
- Dark theme, streaming, cancel, multi-line paste
- Real-time shell output, thinking blocks
- Markup escaping, message queue (drain every 50ms)
- Approval mode indicator, worker error recovery
- Input history, session reuse

#### Shell guard
15 destructive patterns blocked. `force=True` bypasses.

#### LLM agent loop (llm.py)
- Parallel tool execution via ThreadPoolExecutor
- Session reuse (one requests.Session)
- Exponential backoff retry (1s, 2s, 4s) on 429/5xx
- max_turns default 100

### Flags
```
  --workspace PATH    Set workspace root (default: cwd)
  --stream            Stream responses token-by-token
  --quiet             Suppress tool execution logs
  --no-color          Disable ANSI colours
  --approve           Ask confirmation before write/destructive tools
  --allow-overwrites  Allow overwriting files outside workspace
```


## 2026-05-11 — "tool names must be unique" 400 error

**Problem:** After fixing the message ordering bug, a second 400 error appeared:
`tool names must be unique`

**Root cause:** The TOOLS list in `tools/__init__.py` had 21 entries with
duplicate names — `write_scratchpad` (3x), `find_usages` (3x), `verify` (2x).
These were appended by previous self-update attempts without removing old
definitions.

**Fix:** Deduplicated TOOLS by function name (keeping first occurrence).
21 tools → 16 tools.  Test count went from 212 to 246 (34 tests were
silently breaking on the duplicates).

## 2026-05-11 — Lowered default max messages from 500 → 300

**Rationale:** 500 messages is technically fine for a 1M context window but
wasteful. Every turn reprocesses the full history, driving up cost and latency.
Model attention also degrades in the "middle" of very long contexts. 300 messages
(~100+ full turns) is plenty for complex sessions; summarization fills the gap
for pruned context.

**Change:** `memory.py` `DEFAULT_MAX_MESSAGES`: 500 → 300

## 2026-05-11 — Performance + DRY refactoring round

**Single-pass symbol index** (`tools/search_ops.py`): `build_symbol_index()` used
two `os.walk()` + two `open()` per .py file (first for defs, second for refs).
Merged into one walk: collect defs + raw word refs in a single pass, then filter
raw refs to known names after the walk. Halves I/O for index building.

**Semantic search mtime guard** (`tools/search_ops.py`): `_sem_index()` was
`os.walk()`-ing on every `semantic_search` call even when no files changed. Added
a quick stat-only pre-check that compares max .py mtime against stored value;
returns immediately if nothing changed. Avoids redundant walks in repeated queries.

**DRY export conversation** (`memory.py`): Extracted `export_conversation_markdown()`
from two nearly-identical copies in `mini_agent.py:_export_conversation()` and
`tui.py:_export_to_file()`. Both callers now delegate to the shared function.

**DRY workspace resolution** (`config.py`): Moved `resolve_workspace()` from
`mini_agent.py` (with duplicate inline logic in `tui.py:on_mount()`) to `config.py`.
Both entry points now import and call the same function.

## 2026-05-11 — TUI table buffer crash fix

**Bug:** `MarkupError: closing tag '[/code]' at position 0 doesn't match any open tag`.
Table rows were buffered in `_table_buf` but never flushed at turn end — if an
agent response ended with a table, rows carried over to the next turn, and the
`[code]`/`[/code]` wrapper could land out of order.

**Fix:** Flush `_table_buf` in `_finish_turn` (before `_flush_buf`). Add
defensive clear in `_submit`.

## 2026-05-11 — Startup context injection

**What:** At session start, inject a system message with a workspace file tree,
STATE.txt excerpt, and recent git log. Saves 2-3 discovery turns.

**How:** `config.py:build_startup_context()` generates the context string.
Both `mini_agent.py:main()` and `tui.py:on_mount()` prepend it as the first
system message (before the main prompt and any restored history).

## 2026-05-11 — Agent improvement round: checkpoint, edit-hint, diff tool

**Pre-turn checkpoint** (`llm.py`): After the first tool round, inject a transient
message listing files modified so far and suggesting which test files to run.
Prevents the agent from losing track of what it changed.

**edit_file pre-verification hint** (`tools/file_ops.py`): When `edit_file` fails
with "old_string not found", scan the file for lines containing the first 30
chars of the search string and include up to 3 candidates in the error hint.
Helps the agent self-correct typos/whitespace mismatches.

**Standalone diff tool** (`tools/file_ops.py`, `tools/__init__.py`): New `diff`
tool. Runs `git diff` for the workspace or a specific file. Returns raw diff
output or "No unstaged changes." Useful for verifying edits before committing.

## 2026-05-11 — Scratchpad prominence + smart test detection

**Scratchpad prominence** (`prompt.py`): Moved scratchpad guidance from the
"Memory & context awareness" section to its own prominent section right after
Behavior. Added specific guidance: structure with headings, update after every
tool round. Aims to increase scratchpad usage.

**Smart test detection** (`tools/shell_ops.py`): Enhanced `_verify` to check
