### Shell guard (run_shell)

15 destructive patterns blocked (`rm`, `rmdir`, `dd`, `mkfs`, `mkswap`, `chmod 777`,
`chown`, `>/dev/`, `format`, `wiped`, `wipefs`, `parted`, `fdisk`, fork bomb,
`>/dev/null && rm`). `force=True` bypasses.

### Search + lookup strategy

| What you need | Tool |
|:---|:---|
| Function/class definition location | `find_symbol` (fast, startup-indexed) |
| Exact pattern (regex) | `search_files` with `regex: true` |
| Case-insensitive substring | `search_files` with `ignore_case: true` |
| Code by meaning / concept | `semantic_search` |
| Documentation, APIs, current info | `web_search` |

### Tool cache

Read-only tools (read_file, file_info, list_directory, search_files, semantic_search,
web_search) are cached within a turn by (name, sorted_args). `clear_tool_cache()` is
called at turn start by `run_agent_turn`. Write tools and streaming calls skip the cache.

### Error hints

Every common failure path includes a `Hint:` line:
- read_file not found → "Check the path spelling. Try list_directory."
- write_file blocked → "Use a path inside the workspace."
- edit_file mismatch → "Check whitespace, indentation. Try read_file first."
- run_shell error → "Check command and flag spelling. Try with --help."
- destructive guard → "Use force=True to bypass."
- exit code 127 → "Command not found. Check the spelling."

### TUI (tui.py)

- **Dark theme**: #111111 background, #1b1b1b surface
- **Streaming**: Thinking flushed on sentence boundaries (. ? ! :) or every ~400 chars,
  with `┃` left-border prefix for visual grouping. Content flushed on newlines or
  every ~300 chars at word boundaries.
- **Shell output**: streamed in real-time (dim) via `_ToolOutput` messages from the worker.
- **Thinking separator**: `▔▔▔ thinking ▔▔▔` header marks the start of each reasoning block.
- **Parallel tools**: `⫼` icon with connected visual for parallel calls, `⚙` for singles.
- **Plan display**: agent states plan as text before tool calls begin.
- **Markup safety**: all user/LLM content escaped via `_safe()` to prevent Rich markup errors.
- **Multi-line input**: TextArea widget. Enter submits, Shift+Enter inserts newline.
- **Cancel**: Ctrl+C sets cancel flag, worker thread exits cleanly. Memory saved on cancel.
- **Queue architecture**: AgentWorker → thread-safe Queue → set_interval(50ms) drain loop.
- **Shared agent loop**: `run_agent_turn()` in llm.py used by both TUI and terminal REPL.
- **Double-submit guard**: Enter is ignored while a worker is active.
- **Token usage**: displayed in status line (e.g. `— 42 msgs | 1.2k tok | turn 3 | model`).
- **Commands**: `/clear` resets memory, `/help` lists commands.
- **Input history**: Up/Down when empty cycles through submitted messages.
- **Session reuse**: one requests.Session per app session, reused across all turns.

### Flags (both mini_agent.py and tui.py)

```
  --workspace PATH    Set workspace root (default: cwd)
  --stream            Stream responses token-by-token (terminal only; TUI always streams)
  --quiet             Suppress tool execution logs
  --no-color          Disable ANSI colours (terminal only)
  --help, -h          Show usage
```

### LLM agent loop (llm.py)

- **Parallel tool execution**: When the LLM returns 2+ independent tool calls, they run
  concurrently via ThreadPoolExecutor. Single tools stay inline.
- **Session reuse**: One requests.Session per app session eliminates per-turn TCP+TLS.
- **Progress checks**: Every 5 tool-using turns, a user-role reminder asks the agent to
  assess progress and decide whether to continue or wrap up.
- **max_turns**: Default 100 (effectively unlimited; user controls cancellation).
- **Retry**: Exponential backoff (1s, 2s, 4s) on 429/5xx. Connection-drop resilience.
- **Streaming shell**: `on_tool_output` callback passed through to `execute_tool` →
  `_run_shell` → Popen reader threads → real-time TUI display.

### Memory (memory.py)

Three-tier memory management applied on every save:

1. **Token-aware pruning** — `max_tokens=800_000` (~1M context). Rough estimator
   (4 chars ≈ 1 token) prunes oldest turns, preserving tool-call sequences and
   turn boundaries. `max_messages=500` is a hard cap applied first.
2. **Tool result compression** — Tool outputs >6 messages from the tail are trimmed
   to their first line only.
3. **Conversation summarization** — When pruning drops turns, a synthetic
   "Earlier in this conversation: …" message lists files read/written, commands
   run, and recent user prompts.

### Prompt (prompt.py)

- **Confirm before planning**: agent must confirm the plan with the user before starting
  a new feature.
- **Parallel tools**: tells the agent to batch independent tools in one response.
- **Multistep planning**: tells the agent to state the plan in 1-3 sentences before
  executing tools. Example: "I'll read config.py, search for references to the old key,
  then update all three files."
