PRINCIPLE 3: No circular imports. No global mutable state unless unavoidable.
--------------------------------------------------------------------------------

  [P3.1] tools/agent_ops.py, line 32-33
  Issue: Module-level global mutable list + lock for inter-agent messaging.
    _AGENT_MSGS: list[dict] = []
    _AGENT_MSGS_LOCK = threading.Lock()
  This is a global mutable list shared across all agent threads. The lock
  mitigates races but the mutable global still exists. The same data is already
  stored in AgentRuntime.inboxes (thread-safe). Consider deprecating _AGENT_MSGS
  and routing all messages through the runtime. At minimum, document that this
  is a legacy compatibility shim.

  [P3.2] eval/scorer.py, line 24
  Issue: Global mutable dispatch table _CHECKERS: dict[str, callable] = {}.
  Populated via @_register decorator side effects. This is the same pattern as
  tools/__init__.py, so it's consistent, but it is global mutable state.

PRINCIPLE 9: Prefer readable code over clever code.
--------------------------------------------------------------------------------

  [P9.1] tools/agent_ops.py, line 157 (and many others throughout the file)
  Issue: Repeated pattern accessing tool context internals via __dict__:
    runtime: AgentRuntime = _TOOL_CONTEXT.__dict__.get("_agent_runtime")
  This breaks encapsulation of AgentContext. It's used in at least 10 places
  across agent_ops.py, sub_agent.py, and agent_patterns.py.
  Fix: Add proper accessor methods/properties on AgentContext, or pass runtime
  as an explicit parameter rather than reaching into __dict__.

  [P9.2] tools/agent_messages.py, lines 148-155
  Issue: _TYPE_CHECKERS uses lambdas for type checking, which produce opaque
  tracebacks. Example:
    "string": lambda v: isinstance(v, str),
  Fix: Use named functions like _check_is_string(v) for better debug-ability.

  [P9.3] tools/agent_patterns.py, line 115 and 198
  Issue: Direct access to runtime._condition (private attribute):
    with runtime._condition:
        runtime._condition.wait(timeout=min(0.5, remaining))
  This breaks encapsulation. The condition variable is an implementation detail
  of AgentRuntime.
  Fix: Add a public wait_for_completion(timeout) method to AgentRuntime.

  [P9.4] tools/agent_ops.py, lines 468-482 (collect_any)
  Issue: `list(candidates)` is materialized from a set then iterated. The
  comment says "# materialize for iteration" but this is a non-obvious
  workaround for dict/set mutation during iteration.
  Fix: Use `list()` directly in the loop or restructure to avoid the need
  to materialize.

THREAD SAFETY ANALYSIS
--------------------------------------------------------------------------------

  [TS.1] agent_runtime.py: Thread safety is well-designed.
    - All public methods use `with self._lock`.
    - store_result() notifies condition variable.
    - mark_abandoned() handles zombie cleanup.
    - Minor: active_count property acquires lock and iterates self.tasks.
      store_result() pops from self.tasks, so the property correctly counts
      only running tasks. However the `tid not in self.results` check is
      redundant since store_result already removes from self.tasks. No bug,
      just dead logic.

  [TS.2] tools/agent_ops.py: _AGENT_MSGS with _AGENT_MSGS_LOCK is thread-safe
  for append/read, but there's a TOCTOU between len() and append (count may be
  stale by the time the ToolResult is returned). Low severity since it's just
  a display count.

  [TS.3] tools/agent_patterns.py: fan_in() (line 103-116) iterates pending
  while holding no lock on runtime, checking status via get_status() which
  acquires the lock internally. This is safe but may miss completions between
  checks. The condition.wait() with timeout mitigates this.

  [TS.4] eval/runner.py, line 258: threading.Timer used for timeout. The
  _timeout callback sets cancel_event, which is checked by the agent loop in
  another thread. This is safe (threading.Event is thread-safe).

  [TS.5] eval/metrics.py: MetricsCollector has no locking. It's designed to be
  called from a single thread (the agent loop). The `_current_batch_size` field
  is reset on mark_turn(). Safe under single-threaded use, but if callbacks are
  ever invoked from multiple threads, Counter operations would need locking.

ADDITIONAL FINDINGS
--------------------------------------------------------------------------------

  [AF.1] tools/agent_ops.py, line 85 vs tools/agent_ops.py, line 107
  Issue: In _runner(), 'visible' sets config.stream = True. This mutates the
  parent's config object, which is shared across all sub-agents. If two
  sub-agents are spawned simultaneously with different 'visible' settings, this
  is a race condition on config.stream.
  Fix: Copy the config or set stream on a per-sub-agent basis without mutating
  the shared config.

  [AF.2] eval/scorer.py, lines 96-98
  Issue: open(path, "r").read() without a context manager. If read() fails,
  the file handle leaks.
  Fix: Use `with open(path, "r") as f: content = f.read()`.

  [AF.3] sub_agent.py, lines 111-121
  Issue: Token budget warning is injected as a _transient user message every
  turn (after turn 1). This may clutter the sub-agent's context. The parent
  agent loop presumably does the same, so this is consistent behavior, but the
  budget constant (64000) should be shared with the parent loop.

  [AF.4] tools/agent_ops.py, lines 157, 164, 221, 282
  Issue: 'config' is retrieved from _TOOL_CONTEXT.__dict__.get("_agent_config")
  but its type is never validated. If the context was set up incorrectly, this
  will fail with an opaque AttributeError later.
  Fix: Add an isinstance check or rely on a typed accessor.
